# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
cargo build                       # build lib + all bins
cargo test                        # all integration tests (tests/*.rs)
cargo test --test models          # one test file
cargo test test_calibration_metrics   # one test by name (substring match)
cargo clippy --all-targets        # lint
cargo fmt                         # format (no rustfmt.toml; uses defaults)
```

Runnable binaries (`src/bin/`): `run_backtest` (simulated markets), `run_backtest_real` (real markets from CSV/JSON), `download_polymarket_history`, `capture_prices`, `weather_dashboard`, `kalshi_pilot` (real-money pilot, dry-run by default), `example_workflow`, `live_trading_example`. CLI flags are parsed by hand (see gotchas). Two real-data flows:

- **Real-data backtest:** `download_polymarket_history` → CSV → `run_backtest_real --markets <csv>`.
- **Forward calibration:** Polymarket purges price history shortly after a market resolves, so real entry prices only exist while markets are live. `capture_prices` (run daily; a launchd agent `com.polymarketweather.dailycapture` drives it via `scripts/daily_capture.sh`) snapshots every active weather market's price + model estimate to `data/captures.jsonl` and fills in outcomes as markets resolve. `weather_dashboard [--markets <csv>] --output dashboard.html` renders calibration (Brier / ECE / reliability) + the forward trading-strategy readout (edge threshold → fractional Kelly → compounding PnL, hit rate, per-venue/city/market-type breakdown, open book), fetching weather once per city into `data/weather_cache/` (`--refresh` re-fetches). `--markets` is optional: omit it to render the forward readout from captures alone. Strategy knobs: `--edge-threshold` / `--kelly-fraction` / `--max-position-pct` / `--bankroll` (default to `config`/`backtest_params`), plus filters `--sell-only`, `--min-price` and `--raw-edge`. Shrunk-edge is the DEFAULT since 2026-07-19 (`--raw-edge` restores raw disagreements; `--shrink-edge` is a legacy no-op): it led the A/B tracker every day of its two-week window (+5.0% ROI / 35% edge capture vs +2.2% / 11% raw at the 631-settled-trade checkpoint) and its walk-forward λ makes that lead out-of-sample by construction. λ is a per-venue through-origin regression of realized on claimed edge, fitted walk-forward on resolved lead ≥ 1 captures — lead ≤ 0 rows are excluded from the fit because their prices already embed the outcome. Forward evidence (July 2026, 606 settled trades at the 07-26 checkpoint): the model realizes only ~⅓ of the edge it claims (λ ≈ 0.37 Polymarket / 0.34 Kalshi — both DOWN from 0.48/0.61 a week earlier, with trailing-14d slopes 0.23/0.21 approaching the pilot's 0.2 `--lambda-floor`), SELLs carry essentially all the PnL (BUY longshots are break-even), and the 5–10% edge band loses outright. The dashboard's Filter A/B table tracks these candidates against the default so they earn out-of-sample evidence before any becomes the default; at the 07-26 checkpoint the two strongest are **shrunk + edge ≥ 10%** (269 trades, +17.5% ROI, 96% capture vs the default's +8.0% / 62%) and **shrunk + price ≥ 0.10** (402 trades, +9.9% / 78%). Note the price floor and SELL-only turn out to be near-redundant — stacked they give 351 trades / +9.9% vs SELL-only's 353 / +9.9% — so the floor is the more general statement of the same effect and keeps some profitable BUYs. Both cuts were chosen by inspecting this same sample, so their lead is in-sample until the tracker accrues forward rows.
- **Two venues, one pipeline:** `capture_prices` pulls both Polymarket and Kalshi into the same `WeatherMarketRow`. Kalshi MARKET DATA is fetched anonymously from the public production host (`config::kalshi_public_base_url`, api.elections.kalshi.com) — real prices, no creds — scanned per weather series (`WEATHER_SERIES` in `src/api/kalshi_history.rs`; an untargeted `/markets` scan never reaches them). The anonymous market list NULLS price fields, so the per-market public ORDERBOOK fills `best_bid`/`best_ask` and the mid replaces the last-trade fallback. Kalshi gotchas the parser encodes (each cost real calibration before the fix): the target day comes from the TICKER (`KXHIGHNY-26JUL04-…`) because close/expiration times are the morning AFTER; `greater`/`less` strikes are STRICT (floor 105 = "106° or above" ⇒ threshold 106); titles say "high temp", not "temperature". RSA-PSS signing (`KALSHI_API_KEY_ID` + `KALSHI_PRIVATE_KEY_PATH`/`_PEM`, `config::kalshi_base_url` = demo by default) is only for future TRADE endpoints (`has_trade_auth()`). Every row/capture carries a `source`; old captures default `"polymarket"`. Snapshots also store `best_bid`/`best_ask` (both venues) so the dashboard can price edge at EXECUTABLE prices — `decide()` fills BUYs at the ask and SELLs at the bid, falling back to the last trade only for legacy rows without book data. Fresh snapshots additionally carry LOG-ONLY research fields (nothing in the trading path reads them; older rows default None): venue attention proxies (`volume`/`volume_24h`/`open_interest`/`liquidity` — does hype money widen mispricing?), target-day smoke (`pm25_max`/`us_aqi_max` from Open-Meteo's air-quality API at city coords — heavy wildfire smoke suppresses daily highs and the blend only partly prices it), and AI-model daily highs (`forecast_high_aifs`/`forecast_high_aigfs`, the `AI_LOG_CANDIDATES` in `open_meteo_fetcher.rs` — per logical model an ordered (endpoint, name) candidate list with an hourly-collapse fallback, because the July 19 capture proved single guessed names silently fail; the daemon prints which candidate served each model, or that all failed, once per run; fetched one model per request at the same coords the row was priced at. Slot 1 was GraphCast until 2026-07-22 — it never logged a value because NCEP discontinued GraphCastGFS/EAGLE in Dec 2025; NOAA's operational successor AIGFS, `ncep_aigfs025` on Open-Meteo since Jan 2026, replaced it and the never-populated `forecast_high_graphcast` field was dropped), and since 2026-07-23 ensemble member spreads (`ensemble_spread_ecmwf`/`ensemble_spread_gfs`: std-dev °C across ensemble members' daily highs for the target day, `ENSEMBLE_LOG_CANDIDATES` via the separate `ensemble-api` host, same candidate-list + per-run-diagnostic pattern; ≥8 members or the date is dropped — the DAY-SPECIFIC uncertainty candidate, because the pricing σ is a per-(city, lead) constant that prices locked-in and coin-flip days identically; a spread→σ mapping must be fitted walk-forward and beat the constant-σ tables before any dynamic σ enters pricing). The AI models must beat `BLEND_MODELS` on accrued captures BEFORE entering the blend — changing the blend invalidates the fitted sigma/bias tables. Analysis scripts over accrued captures, each with a dated "First look" verdict in its docstring: `scripts/microstructure_lambda.py` (λ conditioned on book/attention microstructure — first look: Polymarket books wider than ~2¢ have NEGATIVE executable-price λ (−0.29), a live Filter-A/B candidate; Kalshi non-monotone, needs data) `scripts/fit_tail_distribution.py` (Student-t vs Normal residual tails, censoring-aware because off-ladder days resolve on open-ended markets and dropping them truncates exactly the tail being fitted — first look: t(ν≈2.5–3) wins the likelihood decisively but walk-forward bucket Brier by only ~0.5% with the gain attributable to scale not tail shape, so the Normal CDF stays), and `scripts/lambda_diagnostics.py` (why λ is ~0.35 and what would raise it — see **λ is a scoreboard** below).
- **λ is a scoreboard, not a knob** (`scripts/lambda_diagnostics.py`, first look 2026-07-26, 1864 resolved lead ≥ 1 rows). λ tracks the model's Brier edge over the market almost one-for-one by week: +0.027 edge → λ 0.85 (wk 06-29), −0.022 → λ 0.09 (wk 07-13), −0.003 → λ 0.42 (wk 07-20). It rises only when the model gets *sharper than the market*; nothing else moves it. Both pricing-side hypotheses are dead on this sample: the σ sweep is Brier-optimal at exactly c = 1.0 and widening σ LOWERS λ (0.305 → 0.192 at c = 2.0), and estimates are well calibrated in aggregate (model 0.2–0.3 realizes 0.257; through-origin slope 0.854); the 07-20 seasonal refit already fixed the bias (Kalshi weekly residual −0.80/−1.18 → −0.04 °C), and a further walk-forward bias correction moves Brier only 0.1026 → 0.1020 while LOWERING λ. What remains is heterogeneity, on an axis the strategy does not currently filter: **sub-10¢ markets carry negative λ on BOTH sides** (BUY −0.086 n=778, SELL −0.105 n=203) while everything ≥ 10¢ is healthy (BUY +0.363 n=219, SELL +0.540 n=664). That reframes "BUYs are worthless" — the dead segment is the TAIL (981 of 1864 rows), where the model's own Normal tail carries no information, not the buy side. Secondary axes: shape (temp_at_most +0.671 / temp_at_least +0.366 / temp_bucket +0.239) and city (kalshi/Miami +0.768, kalshi/Austin +0.750 vs kalshi/Chicago −0.250, polymarket/Istanbul −0.618). All of it is WITHIN venue, yet `ShrinkageFit` fits per venue only (kalshi 0.341 vs polymarket 0.391) — so the fit averages healthy and anti-signal segments together, and **conditioning λ on (venue, segment) is the standing next structural change**: it would zero out the bad segments by construction instead of needing a hand-picked filter. Neither logged sharpening candidate is ready (AIFS RMSE 2.31 °C vs the blend's 1.46; ensemble spread only 67 usable rows) — both stay log-only.
- **Station-aware pricing (how active temp markets are actually priced):** the two venues resolve on DIFFERENT truth variables at DIFFERENT stations, and `src/stations.rs` holds a verified table per venue (`station_for(city, source)`). Polymarket: **Wunderground daily-history max** — max of whole-degree METAR obs at the named airport, NOT the NWS CLI high (often 1°F higher) — traps: Denver→KBKF Buckley (not KDEN), London→EGLC City (not Heathrow), Dallas→KDAL Love (not DFW); reproduced 48/48 settled captures across 28 mapped cities incl. internationals (all °C). Four cities are deliberately UNMAPPED (legacy path): Hong Kong (resolves on the HK Observatory climate extract, one-decimal °C, no METAR), Moscow, Istanbul, Tel Aviv (non-Wunderground national sources). Seoul is mapped but honestly wide (σ≈3.4: Incheon is an island; the forecast grid cell is mostly sea). Kalshi: **NWS CLI daily max** (continuous sensor, ≥ ob-max by 0–2°F, so its `post` phase carries a fitted bias/σ instead of being exact) — traps: Kalshi Dallas→KDFW, NYC→Central Park, Houston→Hobby, Denver→KDEN; every row re-scored 402/402 settled 2026 markets (6,030 total). Each row has per-(city, lead k∈{0,1,2}) `sigma`/`bias` (°C) fitted Jan–Apr 2026 at the daemon's exact capture geometry (15:00 UTC ≈ the 9am launchd run — refit if the schedule hour changes). `capture_prices::StationPricer` prices per phase: local day over ⇒ ob-max (+ venue post bias/σ); day-of ⇒ max(running ob max from IEM `obhistory.json` — near-real-time; the bulk asos.py archive lags a day at some stations — remaining-hours live forecast at STATION coords); lead k ⇒ station-coords forecast + fitted bias/σ. Unmapped cities, precipitation, or failed fetches fall back to the legacy `evaluate_markets_with_forecast` path (downtown coords, σ=2.0). Refit constants from accrued captures (`forecast_high`/`forecast_sigma` stored per snapshot) as seasons drift. First seasonal refit landed 2026-07-20 (k=1,2 slots only; k=0/post untouched): realized highs recovered from winning bucket markets showed a venue-pooled summer over-forecast the winter fit couldn't see (−0.50 °C Polymarket / −0.98 °C Kalshi — a full 2 °F bucket) plus per-city empirical-Bayes deltas (largest: Kalshi LA −2.0 °C, July marine layer), σ rescaled ×1.32 PM / ×0.9 Kalshi; walk-forward validated +5% bucket Brier. `scripts/refit_station_tables.py` reproduces the fit for the next refit. Legacy (unmapped) cities carry the analogous `LEGACY_SUMMER_BIAS_C` in `capture_prices` (Istanbul −1.55 °C was generating fake SELL edges).
- **Kalshi pilot (`kalshi_pilot`):** the evidence-backed config at pocket-change size — Kalshi only, SELL only (executed as BUY NO limit orders; max loss = price paid), lead ≥ 1 only, thresholded on the shrunk edge λ·(bid − model) (λ fitted from `captures.jsonl` via the shared `backtesting::ShrinkageFit`, same lead ≥ 1 hygiene) which must also clear the Kalshi fee `ceil(0.07·C·P·(1−P))` plus `--fee-buffer`. Prices markets with the SAME `StationPricer` as the capture daemon (both now import it from `data_pipeline::station_pricer`). Flat `--stake` sizing (measurement, not Kelly), `--max-exposure`/`--max-orders` hard caps, `PILOT_DISABLE=1` kill switch, automatic circuit breakers (stand down, before the trade API is touched, when fitted λ < `--lambda-floor` [0.2] or the trailing-7-day realized PnL of its own settled orders — joined to capture outcomes, mode-scoped so dry runs rehearse on dry rows — breaches `--max-weekly-loss` [$50]; resuming is a human decision), a per-(city, target-day) correlated-exposure cap `--max-city-exposure` [2× stake] because same-day buckets settle on one daily high, and idempotent re-runs (dedupes against held positions, resting orders, and its own ledger `data/pilot_trades.jsonl`, which records every decision incl. skips for paper-vs-real comparison). DRY RUN unless `--live`; trade host is `config::kalshi_base_url` (demo default — real money requires BOTH `--live` AND `KALSHI_BASE_URL` pointed at prod). Trade endpoints live in `api::kalshi_trade::KalshiTradeClient` (reuses the RSA-PSS signing from `kalshi_history`).
- **Trade where the information edge is.** Measured out-of-sample on settled captures: at lead ≥ 1 the model's bucket Brier beats the market ~3× (0.034 vs 0.099); day-of (lead 0) the market's intraday info beats even a leak-optimistic reconstruction (0.104 vs 0.127) — all of the original −8.1% forward loss came from day-of trades. The dashboard therefore skips lead-0 trades by default (`--trade-day-of` re-enables; per-lead PnL breakdown + filter A/B tracker show the forward evidence).

## Architecture

Rust port of a Python weather-market trading system. The Python original is archived verbatim under `archive/python-legacy/` with a mirrored module layout — consult it when a Rust port behaves unexpectedly or a feature looks missing.

**Pipeline (the core data flow, spanning many files):**

1. **Fetchers** (`src/data_pipeline/*_fetcher.rs`) — one struct per weather source, all exposing `fetch_location(key, start, end) -> Vec<WeatherRecord>`. Free sources (open-meteo, nws, noaa, awc) always run; API-keyed sources (owm, visual_crossing, weatherapi, tomorrow_io, accuweather) implement `is_available()` and are **silently skipped when their key is unset**. A failed/erroring fetch returns an empty `Vec`, never panics — degradation is by design.
2. **`MultiSourceAggregator`** (`multi_source_aggregator.rs`) — calls every fetcher, groups records by date, and averages each field across sources. A day is marked `is_validated` only when ≥2 sources agree. This is the single funnel all weather data flows through.
3. **`BayesianWeatherModel`** (`models/bayesian_model.rs`) — despite param names like `mcmc_draws`/`tune`, there is **no MCMC**. It uses closed-form conjugate updates: Normal–Normal for temperature, Beta–Bernoulli for precipitation occurrence. Predictions sample from the posterior with **fixed per-method seeds** (42/43/44/45) so results are deterministic.
4. **`MarketSimulator`** (`backtesting/market_simulator.rs`) — synthesizes markets from weather: computes rolling **climatological** probabilities and prices each market at that prob plus seeded Gaussian noise. Used only in simulated-backtest mode.
5. **`BacktestEngine`** (`backtesting/backtest_engine.rs`) — the orchestrator. Walk-forward: for each market date it trains a *fresh* model on the trailing `model_lookback_days` window (needs ≥14 records), computes `edge = estimate − price`, filters by `edge_threshold`, sizes with **fractional Kelly** (`kelly_fraction`, capped at `max_position_pct`), and books PnL. Two entry points: `run()` (simulated markets) and `run_with_real_markets()` (markets loaded from CSV/JSON via `RealMarketLoader`).
6. **`PerformanceAnalyzer`** (`backtesting/performance_metrics.rs`) — turns the trade log + portfolio curve into Sharpe, drawdown, return, etc.
7. **`market_estimate` / `evaluate_markets`** (`backtesting/backtest_engine.rs`) — a position-free path used by the dashboard and capture daemon. `market_estimate(model, market)` is the **single place market shapes are priced**: it routes on `market_type` (`temp_at_least`, `temp_at_most`, `temp_bucket`, plus legacy `temperature`/`precipitation`) and respects the market's `unit`. The `precipitation` shape is daily rain OCCURRENCE only — accumulation markets ("Will Seattle have between 2 and 2.5 inches of precipitation in July?") are dropped at parse time by `is_precip_accumulation` in `api/polymarket_history.rs`, because the model has no accumulation forecast and priced every one of them at the ~0.50 Beta prior, manufacturing a +55% edge that went 0-for-6 on settled trades. `evaluate_markets` walk-forward-trains a model per market and returns predicted-prob-vs-outcome rows for `CalibrationAnalyzer` (`models/calibration.rs`: Brier, ECE, reliability diagram).

**Live trading** (`src/api/`): `PolymarketClient` (defaults to paper mode unless real auth is passed) and `LiveTrader`, which wires the same `BayesianWeatherModel` + `MarketMaker` against live orderbooks. Separate from the backtest path.

## Conventions & gotchas

- **Temperature units cross boundaries.** `WeatherRecord` stores °C. Config thresholds and `SimulatedMarket` use °F. Conversions happen at the edges — `backtest_engine::get_model_estimate` converts the °F threshold to °C before calling the model; `market_simulator` converts stored °C to °F. NOAA raw values are in tenths and divided by 10 in `normalize_noaa_data`. Real bucket markets carry an explicit `unit` (`"F"`/`"C"`); `unit: None` means legacy °F (back-compat for old CSVs). Get a unit wrong here and backtests silently produce garbage.
- **Two posterior sigmas — pick the right one.** Probabilities for "will the high exceed / fall in X" markets must use `temp_predictive_sigma` (posterior-mean variance + day-to-day sample variance, ≈ the sample SD, ~8°C), **not** `temp_posterior_sigma` (standard error of the *mean*, which only sizes the mean credible band). Using the latter made the model wildly overconfident — that was the `c4d4304` fix. Honor this when adding any new market shape.
- **`src/cities.rs` is the single source of truth for cities.** `infer_city(title)` matches a market title to a canonical key; `coords(key)` gives lat/lon for fetching. Add a city as one `City` row (key + lowercase title patterns + coords) so title-parsing and weather-fetching can't drift apart.
- **Config is functions, not a loaded struct.** `src/config.rs` exposes `bayesian_model_params()`, `backtest_params()`, `initial_capital()`, etc. Env-backed accessors each call `dotenvy::dotenv()` and fall back to a hardcoded default — there is no global config object.
- **Determinism is load-bearing.** Every RNG is a seeded `StdRng`. Tests and backtests rely on this; don't introduce `thread_rng()` or unseeded randomness in the model/sim/backtest paths.
- **Blocking vs async split.** Weather fetchers use `reqwest::blocking`. Only the Polymarket history downloader (`api/polymarket_history.rs`) is async (`reqwest` + `tokio`); its bin is `#[tokio::main]`. Don't call blocking fetchers from an async context.
- **CLI args are parsed by hand** (no `clap`): a `--key value` loop into a `HashMap`. Match that pattern when adding flags to a bin.
- Errors that cross module boundaries use `thiserror` enums (`RealMarketLoadError`, `PolymarketHistoryError`); internal model/training errors are plain `Result<_, String>`.
